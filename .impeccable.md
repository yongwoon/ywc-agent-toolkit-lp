# .impeccable.md

Design context for `ywc-agent-toolkit-lp`, gathered via `/impeccable teach` during the
2026-08-13 light-theme renewal (see `docs/mission.md` for product-level mission/success criteria).

## Design Context

### Users

Developers evaluating and adopting `ywc-agent-toolkit` (46 skills + per-tool custom agents
for Claude Code and Codex). Two contexts in one site:

- **LP visitor**: scanning hero → problem/solution → features → install → FAQ to decide
  whether to install. Wants to move fast, trust the claims, and find the install command.
- **Guidebook reader**: already installed, reading a skill-usage reference page end-to-end.
  Wants long-form legibility over marketing punch — this is the context that most drove the
  2026-08-13 renewal ("LP 역할과 skill 사용 가이드의 성격을 생각할 때 좀더 차분했으면").

### Brand Personality

Three words, in order of how they were confirmed: **calm, readable, trustworthy/professional**.

The copy voice (`docs/design-system/content-voice.md`: confident, technical, terminal-literate,
"you"-address, no hype) does **not** change — only the *visual* execution does. A confident,
plain-spoken developer doc can be calm rather than neon (Stripe's docs are the reference point:
confident and technical, but quiet).

### Aesthetic Direction

**Theme**: Light only (no dark-mode toggle, no `[data-theme]` branching). Warm-neutral paper
background, never stark `#fff`/`#000` on large surfaces — reuse the existing warm ink ramp
(`docs/design-system/design-tokens.css`), just re-pointed: the 050 end (lightest) becomes `--bg`,
the 900 end (darkest) becomes `--text-bright`, instead of the old dark-theme direction.

**Reference**: Stripe docs/marketing style — generous whitespace, humanist body type, restrained
color, confident hierarchy without visual noise.

**Anti-reference**: the previous "terminal-native / phosphor glow" treatment — dot-grid body
background, scanline texture, blooming `box-shadow` glows on buttons/terminals/badges. These read
as energetic/hacker, which now contradicts "calm."

**Accent**: keep the amber (Claude Code lane) / cyan (Codex lane) hue pair — the lane-color
mapping is functional, not decorative, and switching hue families would erase that meaning for
no benefit. Deepen both for AA text contrast on a light ground (chosen over a full hue swap to
indigo/terracotta — see the compared options): `--accent #8a540a` (5.7:1 on `--bg`), `--link
#1a6e6a` (5.5:1 on `--bg`). Original bright `amber-500 #f5a623` demotes to tint/fill-only use
(badges, dot glows), never body text.

**Typography**: display serif (calm/editorial, replacing the geometric-sans Space Grotesk) +
humanist sans body (replacing IBM Plex Sans) + IBM Plex Mono unchanged, scoped to code/labels/nav
only — mono was already correctly scoped to UI chrome, not reading prose, so it stays as-is.

### Design Principles

1. **Body copy readability is the priority axis.** Humanist sans for prose, generous line-height,
   serif reserved for headings only — never let a display face leak into a paragraph.
2. **One primary accent (amber), used sparingly; cyan is the only secondary**, and both are
   functional (Claude/Codex lane), never purely decorative. Carried over unchanged from the prior
   dark-theme system.
3. **Calm over intensity.** No glow/neon halo shadows, no dot-grid/scanline texture. Depth comes
   from a soft, low-opacity shadow and a hairline border, not a blooming light effect.
4. **Warm neutral, never stark.** Background and text both come off the existing warm ink ramp —
   no pure `#fff`, no pure `#000` on any large surface.
5. **WCAG 2.2 AA is a floor, verified not assumed.** Every accent/text-on-color pairing is checked
   against its actual background before it ships (see the compared-options artifact from this
   session for the contrast math behind the chosen hex values).
